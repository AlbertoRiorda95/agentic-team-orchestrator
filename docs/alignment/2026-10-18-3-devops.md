## What changed
The root `Makefile`, `backend/Dockerfile`, `.dockerignore`, `compose.yml`,
`ci/smoke.sh` and the CI jobs exist, following `docs/design/foundations.md`
and the backend and frontend entries of this task. This entry lists the
runtime constraints and checks the other roles now rely on.

## What the others relied on (before → after)
Makefile (everyone): `make install` (`uv sync --directory backend --locked` +
`npm ci`), `make lint`, `make typecheck` (mypy + `npm run typecheck`),
`make test`, `make build` (`build-web` + `build-image`, tag
`devorchestrator-api:local`, never pushed), `make openapi`; plus `make up` /
`make down` (compose, `GIT_SHA` from the current commit) and `make smoke`.
`--locked` fails when `backend/uv.lock` does not match `pyproject.toml`: run
`uv lock` and commit it.

API image (backend):
- Build context is the repository root, allowlist in `.dockerignore`: only
  `backend/`, without `tests/`, `scripts/`, caches and `.env*`. Runtime
  dependencies only (`uv sync --locked --no-dev`); the project is installed
  (editable, in `/app/.venv`), so the version comes from the package metadata.
- Runs as uid/gid 10001 with `/app` owned by root; compose adds a read-only
  root filesystem (only `/tmp` writable, tmpfs), `cap_drop: ALL`,
  `no-new-privileges`, 1 CPU and 512 MB. The API must not write to disk
  outside `/tmp`.
- Start command, from `/app` (= `backend/`): `alembic upgrade head && exec
  fastapi run --host 0.0.0.0 --port 8000`. A failing migration stops the
  container.
- Image `HEALTHCHECK`: `GET http://127.0.0.1:8000/api/v1/health` (liveness)
  with a 2 s timeout, every 10 s, 30 s start period.

Compose (everyone): project `devorchestrator`; `db` is `postgres:17`, user and
password `postgres`, database `devorchestrator`, port 5432, volume `db-data`;
`api` on port 8000 gets `DATABASE_URL=postgresql+asyncpg://postgres:postgres@db:5432/devorchestrator`
(a `DATABASE_URL` in `.env` does not apply inside compose), `CORS_ORIGINS`
(default `http://localhost:8081`) and `GIT_SHA` from the shell or the root `.env`.

CI (backend, frontend), **written but not on the branch**: GitHub refused the
push of `.github/workflows/ci.yml` (the agent's GitHub App token has no
`workflows` permission). The change below must be pushed by a human (the
patch is in the devops summary of the PR); until then the branch runs the
old `ci.yml`, without the smoke job.
- `build-test` runs every step unconditionally (no more `hashFiles` guards):
  install, lint, type check, contract drift (`make openapi`), **new: API client
  drift** (`npm run gen:api` then `git diff --exit-code packages/api-client`),
  migrations, build, test, `npm run build:mobile`.
- **New job `compose-smoke`** (`ci/smoke.sh`): builds the image, starts the
  stack with `--wait`, expects `/health/ready` = 200 `ok` with
  `checks.database: ok` and a `version` ending in `+<short GIT_SHA>`, a 404
  `application/problem+json` on an unknown path, and, with `db` stopped, a 503
  `down` / `database: failed` within 3 s.

Not done: root `.env.example` (the five variables of the spec and the ports).
devops cannot write that file in this session (permission rule); it must be
added by whoever owns it. Content to add: `DATABASE_URL`, `CORS_ORIGINS`,
`GIT_SHA`, `VITE_API_PROXY_TARGET`, `EXPO_PUBLIC_API_URL` with the spec's local
defaults, and the ports 8000, 5432, 5173, 8081. Note for frontend: Expo reads
`.env` from `apps/mobile`, not from the repository root.
